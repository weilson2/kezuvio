# M6 domain / UI contract

Module `accountingModule`, product `accounting-cloud`. `AccountingView` exported from `packages/accounting/index.ts` extends state in `model.ts` with `asOf` UTC timestamp, `reports`, `canManage`. Manager gets all records; Viewer/Customer get aggregate reports only (no journals/documents/parties/history/bank/inventory). Manager forms use `workspace.act(type,args)`. Expected record versions are mandatory. All amounts are integer sen. Dates are validated `YYYY-MM-DD` business dates. Defaults: view.today and open periods. Fictional MYR demonstration, accrual policy, no tax integration.

Exact action contracts:

| Action               | Exact args                                                                                                                                                                                                                          |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `transaction.post`   | `{kind: 'Income'                                                                                                                                                                                                                    | 'Expense'    | 'Invoice' | 'Bill',date,memo,partyId: string | null,dueDate: string             | null,amountSen}`; party/due required for Invoice/Bill, both null for cash Income/Expense |
| `journal.post`       | `{date,memo,lines:[{accountId,debitSen,creditSen},...]}`; balanced Adjustment, 2–12 nonzero one-sided lines; control AR/AP/inventory prohibited to preserve subledgers                                                              |
| `opening.post`       | `{date,memo,lines:[...]}`; only once, before other postings, no Income/Expense/control accounts; seeded demo already has opening                                                                                                    |
| `document.settle`    | `{id,version,date,amountSen}`; invoice Receipt, bill Payment; positive <= outstanding                                                                                                                                               |
| `document.credit`    | `{id,version,date,amountSen,memo}`; positive <= unpaid outstanding, no cash refund in this increment                                                                                                                                |
| `journal.reverse`    | `{id,date,memo}`; reverse once on/after original date, open period; linked document/settlement/credit effects updated; inventory postings disallowed (compensating future stock workflow), matched bank postings must first unmatch |
| `period.create`      | `{name,start,end}` nonoverlapping bounded periods                                                                                                                                                                                   |
| `period.close`       | `{id,version}` irreversible close for this demo; require no unmatched bank lines in period                                                                                                                                          |
| `account.create`     | `{code,name,category:'Asset'                                                                                                                                                                                                        | 'Liability'  | 'Equity'  | 'Income'                         | 'Expense'}`; unique 4-digit code |
| `party.create`       | `{name,kind:'Customer'                                                                                                                                                                                                              | 'Supplier'}` |
| `bank.match`         | `{id,version,journalId}` matching exact signed Bank amount, one bank line per journal                                                                                                                                               |
| `bank.unmatch`       | `{id,version}`                                                                                                                                                                                                                      |
| `inventory.purchase` | `{id,version,date,quantity,unitCostSen}` stock purchase paid from Bank                                                                                                                                                              |
| `inventory.sell`     | `{id,version,date,quantity,unitPriceSen}` sale received in Bank, weighted-average COGS; current stock/version required                                                                                                              |

Exported pure `accountingReports(state, from = earliest period start, to = state.today): Reports` computes from immutable journal lines and reconstructs dated outstanding subledger balances (including reversals), not current document cached totals. `trial` is the closing trial balance inception-to-to, with one net debit or credit per account; `totalDebitSen`/`totalCreditSen` sum these closing balances. `ledger` contains individual movements within [from,to]; balance sheet/cash/AR/AP are inception-to-to; P&L is [from,to]. `balanceDifferenceSen` must be zero. `bankStatementSen` is net signed fictional statement to report end; `matchedBankSen` is matched statement subset; `unmatchedBankSen` is unmatched subset. Seed statement starts at zero and opening bank balance is represented by a seed statement line. `inventoryValueSen` reconciles posted Inventory account to the selected date. `aging` includes document/reference/party/kind/due/outstanding/age/bucket. For filtered manager UI call the pure helper on manager view; it ignores extra projection fields. Do not use filtered reconstruction on redacted views; show their server default aggregate reports.

Display reversed journal status by `view.journals.some(j => j.reversalOf === original.id)`. Posted journal objects are immutable; reversal appends another journal. Control accounts IDs: `bank`, `receivable`, `inventory`, `payable`, `capital`, `sales`, `cogs`, `expense`.

Stock policy: integer quantities; moving weighted-average perpetual valuation, cost of issued units is `(value * quantity / quantityOnHand)` rounded half up in integer sen, final stock issue consumes all residual value. No backdated stock posting before the last inventory journal date. Inventory journal reversals are deliberately blocked because they would invalidate later cost layers; no deletion of posted inventory history. Bank rows are seeded fictional transactions; no import/integration or fabricated matching differences.
